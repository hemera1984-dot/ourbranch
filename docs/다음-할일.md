# 다음에 할 일 (2026-08-02 검토 결과)

Codex와 자체 검토 두 건에서 나온 지적을 정리한 것. 오늘 처리한 것은 빠져 있다.

## 이번 주 안에 (팀원 늘리기 전)

1. **이름이 사실상 기본키인 구조** — TA 일지(author)와 업적(member)이 이름 문자열로
   소유권을 판정한다. 동명이인이 서로의 기록을 수정할 수 있고, 조직도에서 이름 오타를
   고치면 그 사람의 과거 기록이 전부 남의 것이 된다. 이메일 기준으로 바꿔야 한다.
   → 스키마 변경(author_email·member_email 추가)이라 이관 작업 필요.

2. **일괄 저장이 원자적이지 않다** — TA·업적을 여러 줄 저장하다 중간에 실패하면
   앞 줄은 저장되고 오류가 난다. 다시 저장하면 중복된다. 트랜잭션으로 묶어야 한다.

3. **저장 안 누르고 화면을 옮기면 입력이 날아간다** — 그리드에 쓴 내용이 경고 없이
   사라진다. `hasChanges()`가 이미 있으니 화면 이동·페이지 종료 시 확인만 붙이면 된다.

4. **네트워크 실패 시 입력이 지워진다** — 저장 실패하면 화면을 서버 값으로 다시 그려
   방금 친 내용이 눈앞에서 사라진다. 실패해도 입력을 남기고 오류를 보여줘야 한다.

## 모바일 (대부분 폰으로 쓴다)

5. **TA 일지·업적현황이 폰에서 사실상 입력 불가** — 12열 그리드를 가로 스크롤하며
   채워야 한다. 폰에서는 한 건 입력 폼 + 요약 열람으로 바꾸고, 엑셀 붙여넣기는
   PC 전용으로 명시.

6. **일정 팝오버의 저장 버튼이 키보드에 가린다** — 아이폰에서 칩 10개 + 입력칸이
   올라오면 저장 버튼에 도달 못 한다.

7. **일일보고 팀 현황 표의 첫 열이 안 고정** — 가로로 밀면 누구 건지 모른다.
   주간 확인표에는 이미 적용돼 있으니 같은 방식으로.

8. **상단 탭 7개가 폰에서 넘친다** — 오른쪽 항목(TA·업적)은 스크롤해야 나오는데
   힌트가 없다. 팀원용은 4개(오늘·일정·보고·공지)로 줄이고 나머지는 관리 메뉴로.

## 개념 정리 (구조 문제)

9. **출석 사실과 내일 계획이 한 레코드** — 저녁 6시 이후 보고는 내일 날짜로 잡히는데,
   같은 화면의 '출근'이 내일 출석으로 저장된다. 출석은 당일만, 내일 보고에는
   '출근 예정'을 따로 두는 게 맞다.

10. **부지점장 퇴근길 함정** — 저녁에 "오늘 누가 안 냈나" 보려고 열면 내일 화면이라
    전원 미보고로 보인다. 매번 '이전 날'을 눌러야 한다.

11. **목표 입력칸을 비우고 저장하면 목표가 지워진다** — 화면이 항상 입력칸 값을 보내서,
    빈 칸이면 삭제된다. 팀원 20명 화면에서 실수 한 번이면 조용히 사라진다.

12. **미션 달성률 분모가 현재 인원** — 팀원이 늘면 지난달 100%였던 팀 미션이 80%로
    떨어진다. 부여 시점 대상을 저장해야 한다.

13. **삭제가 전부 즉시·영구** — 구성원을 지우면 그 사람의 일정·일지·업적이 고아가 된다.
    삭제 대신 '비활성' 처리로 바꾸는 게 안전하다.

## 검토자가 "빼라"고 한 것 (판단 필요)

- **주간 확인표 + 일괄 입력 그리드** — 달력이 같은 일을 더 쉽게 한다는 의견.
  다만 사용자가 "팀 전원 한 판" 원칙으로 요구한 화면이라 유지 쪽에 무게.
- **공지 댓글** — "확인 버튼"을 넣은 이유와 중복. 댓글 삭제 기능도 없다.
- **미션 status(요청/진행중/완료)** — 서버 API는 있는데 화면에서 안 쓰는 죽은 코드.
- **강의 신청** — 구분 하나 때문에 권한 분기가 늘었다. 오선택하면 지점 전체 공개.
- **다크모드** — 색 변수 2세트 유지 비용 대비 우선순위 낮다는 의견.
- **지난달 일정 가져오기** — 요일이 아니라 날짜 기준이라 교육·회의가 엉뚱한 요일로 간다.
  요일 기준 반복으로 바꾸거나 빼는 것 검토.

## 운영

14. **백업이 같은 서버에 있다** — 서버·디스크 사고 시 함께 사라진다. 외부(NCP 오브젝트
    스토리지 등)로 복사하고, 백업 실패 시 알림이 필요하다.
15. **.gitignore가 확장자 3개만 막는다** — 저장소가 공개라 백업 파일을 다른 이름으로
    한 번만 커밋해도 후보자 개인정보가 공개된다. 패턴을 넓혀야 한다.
16. **TA 개인정보 후속** — 전화번호 표시 마스킹, 보관기간·파기 규칙, 열람 기록.

## 가장 큰 위험 (기능이 아니라 제품 문제)

**앱에 쓰고 다시 카톡에 붙여넣는 구조.** 예전엔 카톡에 바로 썼는데 지금은
앱 열고 → 채우고 → 저장하고 → 복사하고 → 카톡에 붙여넣는다. 팀원 입장에서는
일이 한 단계 늘었다. 두 검토가 공통으로 "2주 뒤 사용률이 떨어질 가장 유력한 원인"으로 지목했다.

해결 방향은 둘 중 하나다.
- 알림을 앱 안으로 들여와서 카톡 없이도 전달되게 (푸시 또는 최소한 미확인 배지)
- 또는 앱을 "카톡 문구 생성기"로 인정하고, 대신 앱에서만 되는 가치(집계·이력·조회)를 키운다
