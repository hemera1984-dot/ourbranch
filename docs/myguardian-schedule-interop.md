# 마이가디언 ↔ 하랑지점 일정 연동 계약

작성: 2026-07-31, 마이가디언 세션. 양쪽 프로젝트가 이 문서 하나를 기준으로 시공한다.
(ourbranch decisions.md "향후 연동" 절의 확정판 — "마이가디언 서버가 추가"라는 초안과 달리,
미팅 일정은 마이가디언 서버를 거치지 않으므로 **화면 → ourbranch API 직행**으로 확정.)

## 원칙

1. **서버에 고객 실명·연락처를 절대 올리지 않는다.** 고객 표기는 코드(C-YYYY-NNN)만.
   이름 복원은 마이가디언 화면이 자기 로컬 고객 데이터로만 한다. 이 원칙 덕분에
   고객정보 외부 클라우드 규정 게이트(STEP 2 선행 조건)에 걸리지 않는다.
2. **로컬 우선.** 마이가디언 고객관리의 미팅 저장은 지금처럼 로컬 폴더가 원본이고,
   서버 전송은 부가 동기화다. 전송 실패가 미팅 저장을 막으면 안 된다.
3. 인증은 공유 세션 토큰(mg_session) — ourbranch 서버가 myguardian.db 읽기로 검증 (기존 구조).

## API (ourbranch 서버가 구현)

`POST /events/upsert` — 승인 계정만.

```json
{
  "출처": "myguardian",
  "출처키": "mg:C-2026-014:3",
  "종류": "고객미팅",
  "고객코드": "C-2026-014",
  "표시명": "안*민",
  "연락처": "010-****-3016",
  "차수": 3,
  "일시": "2026-08-05",
  "상태": "예정"
}
```

- `표시명`·`연락처`는 **마스킹 표기만** (헌법 외부 반출 마스킹 규칙: 가운데 글자 `*`,
  전화 중간 자리 `****`). 원본 이름·번호는 어떤 필드로도 서버에 오지 않는다.
  마스킹은 마이가디언 화면이 전송 직전에 수행 (2026-07-31 사용자 확정 — 구분 가능성 확보).
- `일시`는 날짜만 올 수 있다 (미팅 차수는 일자 단위) — 종일 일정으로 처리.

- `출처키` = 멱등키 (`mg:<고객코드>:<차수>`). 같은 키 재전송이면 갱신 (upsert).
- `상태`: 예정 | 완료 | 취소. 취소는 삭제가 아니라 상태 갱신 (이력 보존).
- 소유자 = 요청 세션의 계정. 다른 FC의 일정은 못 쓴다.
- 열람 범위는 ourbranch 권한 모델 그대로 (팀원은 자기 팀).
- CORS: `https://app.insurguard.life` 허용 필수 (마이가디언 화면에서 직접 호출).

## 마이가디언 쪽 (마이가디언 세션이 구현)

- `web/customers/` 미팅 차수 저장·완료·취소 시 위 API로 전송.
- 실패(서버 미배포·오프라인·미로그인) 시: localStorage 큐(`mg_event_queue`)에 쌓고
  다음 저장 성공 시 또는 화면 진입 시 재전송. 사용자에게는 방해하지 않는 작은 표시만.
- API 주소는 ourbranch 배포 후 확정 (`https://branch-api.insurguard.life` 형태 예상) —
  마이가디언 쪽은 상수 하나로 두고 배포 전엔 빈 값(전송 비활성).

## 표시 (ourbranch 화면)

- 캘린더/오늘 일정에 `고객미팅 · C-2026-014 · 3차` 형태. 실명 없음.
- 항목 클릭 시 마이가디언 고객 상세 딥링크: `https://app.insurguard.life/web/customers/?code=C-2026-014`
  (이름은 그 기기의 로컬 데이터가 있어야 보인다 — 의도된 동작).

## 미결 (배포 시 확정)

- ourbranch API 도메인·경로 확정 → 이 문서 갱신 → 마이가디언 `BRANCH_API` 상수 채움
  (`web/customers/index.html` — 훅·큐·마스킹은 2026-07-31 시공 완료, 상수만 비어 있음).
- ourbranch events 스키마와 필드명 최종 대조 (한 쪽이 다르면 이 문서 기준으로 맞춘다).
- 활성화 시 마이가디언 고객관리 안내 문구 갱신: 현행 "어디에도 전송되지 않습니다" →
  "미팅 일정만 마스킹 표기로 팀 캘린더에 전송됩니다" (데이터 신뢰성 원칙 — 문구가 사실과 달라지면 안 됨).
