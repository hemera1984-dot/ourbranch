## 2026-07-31 — 프로젝트 출범

- 마이가디언 v2의 우리팀(web/team/) 기능을 독립 프로젝트로 분리한다. 분리와 동시에
  팀 단위가 아니라 **지점 단위**로 확장한다.
- 이름: 저장소·폴더는 `ourbranch` (지점명이 계속 바뀌므로 일반명). 화면 표기 지점명은
  서버 settings 값으로 두고 현재 「하랑지점」.
- 도메인: `branch.insurguard.life` (DNS 추가 예정).
- 브랜드: 마이가디언 패밀리 (네이비+시안 디자인 언어 승계).
- 인증: 마이가디언 세션 공유. ourbranch 서버가 같은 NCP 인스턴스에서 myguardian.db의
  sessions·accounts를 읽기 전용 조회. 재승인 절차 없음.
- 조직: 지점장(BM) → 부지점장(ESL, **팀의 단위**) → 팀장(SSL)·부팀장(GSL)·팀원(FC).
- 권한: 총관리자=안창민(관리자 임명권). 관리자=부지점장 이상(팀원 추가·삭제, 조직도 수정).
  열람 — 총관리자·지점장 전체 / 부지점장 자기 팀(총관리자 승인 시 전체) / 팀원 자기 팀.
- 우선순위: **기존 우리팀 기능 강화(서버화+팀 분리)가 최우선.** 여기에 TA 일지·업적현황이
  시급 항목으로 추가됨. 도입 후보자 파이프라인(14단계)은 후순위.
- 팀 공유 드라이브(구글 드라이브 「신한라이프」) 인벤토리 결과: 도입 프로세스 14단계 폴더
  (가.개인정보취합 ~ 하.메뉴얼)가 있으나 대부분 빈 골격. 실사용은 CIS용 PPT의 팀별·후보자별
  폴더뿐(폴더명 뒤 (완)·(백지)로 진행 표기). 드라이브의 역할을 앱 기능으로 흡수하는 것이 목표.
  드라이브 팀 명명(하랑2팀·미래4팀 등)이 부지점장 단위 팀 구조와 일치함을 확인.
- 기존 web/team/ 화면·데이터는 이관하지 않고 새로 설계한다 (데이터가 사실상 비어 있음 —
  실데이터는 공지 1건).

## 일정표 원칙 (2026-07-31 사용자 확정 — 일정이 이 앱의 최우선 기능)

1. 팀원이 스케줄 입력이 쉬울 것.
2. 자세한 내용까지 입력 가능할 것 — 날짜·시간대·장소를 자유롭고 편하게.
3. 입력한 스케줄을 그 사람의 도입자·부지점장·지점장이 가독성 좋게 확인할 수 있을 것.
   도입자는 팀이 달라도 자기가 도입한 팀원의 일정을 본다 (members.recruiter_email).
4. 같은 팀(같은 부지점장 산하) 팀원끼리 서로의 스케줄을 가독성 있게 확인할 수 있을 것.
   팀 전원이 한 번에 들어가는 스케줄표 하나(주간 확인표)가 기본 화면이다.

구현 상태: 1·2·4 완료(셀 클릭 팝오버 + 장소 필드 + 주간 확인표), 3 완료(도입자 지정·
교차 팀 열람·"내 도입" 줄 표시). 전부 서버 테스트·브라우저 검증 통과.

## 2026-08-02 — 마이가디언 미승인 계정도 하랑지점 가입 신청 허용

부지점장이 구글 로그인을 했는데 승인 화면에 아무것도 뜨지 않던 문제.
마이가디언 계정 status가 `대기`라 auth.js가 토큰을 거부(401) → 프론트가 로그인
화면을 다시 띄우고 `/join`이 호출되지 않아 승인 대기열이 비어 있었다.

결정: **마이가디언 승인과 하랑지점 승인을 분리한다.** 구글 신원 확인은 마이가디언이
이미 했으므로 토큰은 `정지`만 차단하고, 하랑지점 접근 여부는 명단(members)으로만
가른다. 미승인 계정에는 마이가디언 직급·총관리자 권한을 적용하지 않는다
(대기 상태로 BM 행세를 하며 지점 전체를 보는 일이 없게).
